교육 최종 발표의 중심은 유형·유사도별 실패 조건이다.

## 기존 실행: A/B 검수 후 분석

`/home/student/github/sas/00_RUN_AB.sas`를 전체 실행한다. 순서는 11 → 12다.
09·10은 `archive/`로 이동했으며 `00_RUN_PENDING.sas`도 실행 안내만 남긴다.
매 실행은 새 `outputs/ab_20260914_실행별코드/` 폴더를 만들며 기존 결과는 보존한다.

기존 입력 중 원문·행별 예측은 공개본에서 제외했다. 아래 과거 분석에는 별도 승인된 비공개 입력이 필요하다.
기존 보관 출력은 `archive/sas_outputs_20260914/`로 옮겼다. 새 실행은 계속 `outputs/`에 기록한다.

## 전체 과거 분석 재현

`00_RUN_ALL.sas`는 07 → 01 → 02 → 03 → 06 → 05 순서로 시작하며 04는 선택 실행이다.
08은 `sas_fage_abc_rows.csv`가 있으면 실행한다. 09·10은 실행하지 않는다.
현재 확인된 과거 결과를 다시 얻기 위해 전체 실행할 필요는 없다.
08은 원 train fold 0 개발 자료의 시드별 적합이며 01의 평가 범위와 다르다.

02는 유효한 OOF 입력이 있을 때 적합한다. OOF 부재로 건너뛴 결과를 완료로 부르지 않는다.
단독 실행 시 07·08은 독립 실행할 수 있고, 내부 분석은 01부터 시작한다.
04는 활성 CAS 세션 `mysess`와 TextMine/HPL 관련 이용 환경 확인이 필요한 선택 실험이다.

기준으로 쓰지 않는다. 어떤 p값도 미리 정한 합격 숫자가 아니다.

## 보관과 오류 대응

`outputs/`의 단계별 로그·HTML·실행 상태 CSV를 입력 manifest와 함께 내려받는다.
다음 실행 전 이전 결과를 날짜별 폴더로 보관한다. ERROR/WARNING 및 누락 단계를
검수한 뒤 완료 여부를 결정한다. 파일 존재만으로 성공이라고 표시하지 않는다.

오류가 나면 첫 ERROR, SAS 버전, 입력 해시를 기록한다. OOF 검사가 실패하면 입력을
대조하며 in-sample 점수로 우회하지 않는다. `%abort cancel`이 실행을 중단한 경우
최종 실행 상태 CSV가 없을 수 있으며, 완료로 간주하지 않는다.

발표에는 데이터 감사, 실패 확률·CI, 표본 제외 영향, ROC-AUC 차이를 골라 쓴다.
KISA 악성·URL 포함 자료와 선별 정상 도전셋은 현장 대표 표본이 아니다. 현장 유병률을
모르면 조건부 시나리오로 표시한다. 수신 문자 총수만으로는 유병률을 구할 수 없다.
